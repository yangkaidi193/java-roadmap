# ADR-001 认证用手写 JWT，不引入 Spring Security

## 背景

项目一要在 3 周内上线 MVP，认证需要：登录、token 续期、登出、接口鉴权。
时间窗口紧，且这部分是面试深挖重点。

## 选项

| 选项 | 成本 | 风险 | 面试表现 |
|---|---|---|---|
| A. Spring Security + JWT Filter | 现学 3-5 天，配置复杂 | 学不透，被追问就崩 | 中等（人人都会） |
| B. 手写 JWT + 拦截器 + 注解 | 1-2 天 | 安全细节要自己兜 | 强（能讲到协议与实现） |
| C. Session + Redis | 1 天 | 水平扩展要处理粘性 | 弱（老派） |

## 决定

选 **B**。理由：时间成本最低，且「过滤器怎么排、token 怎么续、黑名单怎么存」三个点都能讲透。

## 后果

- 好处：完全可控，能答「为什么不用 Security」——因为它要的不是配置，是你懂不懂鉴权链路。
- 代价：越权、重放、伪造这三个安全点必须自己补，且要在面试里主动说。
- 补齐动作：接口鉴权用注解 + AOP；令牌加 jti 支持黑名单；刷新令牌单独存 Redis 并设滑动过期。

## 什么时候该反悔

- 如果目标公司是金融/大厂基础架构，Security 生态更重要 → 补一版 ADR
- 如果项目要接入 OAuth2 第三方登录 → 换 Spring Authorization Server

## 面试怎么讲（30 秒版）

> 我没有用 Spring Security，因为三周内要上线，而我希望把认证链路讲清楚而不是背配置。
> 我用 JWT + 拦截器 + 注解做鉴权，用 Redis 存 jti 黑名单解决无法主动失效的问题，
> 用滑动过期 + 刷新令牌解决续期。代价是越权和重放要自己防，这部分我做了参数校验和工具白名单。
